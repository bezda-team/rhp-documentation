## Horizontal or vertical

`orientation` on the Chart sets the direction bars run:

- `"horizontal"` (the default): bars run left to right, and slats stack top to bottom, as rows.
- `"vertical"`: bars run bottom to top, and slats sit side by side, as columns.

The same slat works both ways: labels, gaps and rounded ends follow the turn.
A vertical chart is 240px tall unless you set `height` on the Chart.
Give a horizontal chart a `height` too, and slats without a `thickness` share it, so they fit the space you have.

## Slat size and room for text

`slat()` takes two layout settings besides `css`:

- `thickness`: how thick a slat is along the stack, in px: its height in a horizontal chart, its width in a vertical one.
  Leave it out and the slats share what the chart has: a vertical chart's width, a horizontal chart's `height`.
  A horizontal chart with no `height` has none to share, so its slats are 32px each and the chart grows with them.
- `room`: the space the slat's labels need outside the chart, in px. `start` is before the chart, where names go; `end` is after it, where numbers go past the bars.

`room` can also hold `before` and `after`: space above the first slat and below the last.
When the settings differ by direction, give each its own: `thickness: { horizontal: 40, vertical: 60 }`.

The chart makes room for the largest `room` any of its slats ask for, and for its axis numbers.

## Room that fits the names

With `room: "auto"`, the chart works the room out itself: the start is as wide as the widest name, and the end as wide as the widest label there.
It's done in CSS, so a chart drawn on a server has it right too.

<Demo name="layout-auto" height={170} />

You still decide how much room names get, in the slat's CSS: size the label and the room follows.

```css
.name { max-width: 9em; }                 /* longer names end in "…" */
.name:vertical { white-space: normal; }   /* names wrap under their columns */
```

By default a name takes at most 40% of the chart; `--rhp-gutter-max` on a label changes that.
Each side can be set on its own: `room: { start: "auto", end: 40 }` fits the names and keeps 40px at the end.

A few things to know:

- Each slat then reaches into the room as well, so a slat's background runs under its own name.
- Only a label that is a child of the slat's root element is measured. A label inside another element gets no room, and rhp warns about it in the console.
- When the widest name changes, the room changes at once, and the bars resize with it instead of animating.
- Firefox makes the room under a vertical chart one line tall, so names that wrap onto more lines there need `room` in px.

### When px is better

`"auto"` suits charts of tens of slats whose names don't change much.
Give `room` in px when:

- the chart has hundreds of slats,
- its names change often, with new data or `reorder="refill"`,
- many of your readers use Safari.

Each time a name changes, the chart lays out all its slats again to find the widest one, and Safari is the slowest at it.

## Width

A chart is as wide as the element it's in, like any block element.
Set its width with CSS on a wrapper, or with `class` or `style` on the Chart.
