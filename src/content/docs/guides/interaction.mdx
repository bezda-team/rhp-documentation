Charts are HTML, so interaction works the way it does anywhere else on a page.

## Hover with CSS only

Most hover effects need no code: style `:hover` in the row's CSS.

## Clicks

Blocks take handlers like any element: `onClick`, `onPointerEnter`, `onKeyDown`.
With many rows, one handler around the chart is simpler: mark blocks with a `data-` attribute and find it with `closest`.

What the handler decides goes back into the Plot as data.
Here the picked city becomes `d.faded` for the other rows, and their CSS fades them.

## Keyboard

Add `keyboard` to a Plot, and its rows take focus.
Tab stops at one row of the chart, the arrow keys go to the row shown before or after it, and Home and End to the first and the last.
Style `:focus-visible` next to `:hover`, and what the pointer shows, the keyboard shows too.

<Demo name="interaction-keyboard" height={200} />

- **Tab comes back to the row focused last**, so a reader who leaves the chart picks up where they were.
- **The keys follow the order on screen**, also when the rows are sorted, and a row keeps its focus when it moves.
- **For code, use `onFocus`** on the row, as you would `onPointerEnter`.
- **A key that something inside the row uses stays with it**: a field, or a handler that calls `preventDefault()`.

A `<button>` inside a Label (a name you can click, for example) gets focus and keyboard presses on its own, in a Plot with or without `keyboard`.

## Good to know

- **Follow the pointer with `pointermove`, not `pointerover`.** When a hover changes the layout (a badge appears), the browser can fire `pointerover` again under a pointer that hasn't moved.
- **A Plot drawn over another one covers it.** Give an overlay, such as a line marking today, `style={{ "pointer-events": "none" }}` so the pointer reaches the Plot under it.
- **Page listeners and tests work as usual.** Charts are plain elements in the page: `querySelector`, testing libraries and click listeners all see them.
