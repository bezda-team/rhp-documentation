You style a chart with plain CSS, written next to the slat it styles.

## CSS for a slat

Wrap the slat function in `slat()` and give it `css`.
Put classes on the slat's root and its blocks, and style those classes.

<Demo name="styling-slat" height={260} />

That CSS only reaches this chart's slats.
It can't leak into your page or into other charts, so you can use short class names like `.slat` or `.value` without worrying.
It works in both directions: your page's CSS can't reach into a chart either, unless you [turn that off](#without-the-guard) to draw faster.

Anything CSS can do to an element, it can do here, because a block and a slat are ordinary elements.
A gradient on a bar, a web font on a label, an image behind a cell: all of it behaves the way it does anywhere else on your page.

## Using someone else's look

A slat's CSS can be a list, which is joined in order:

```jsx
import { NIGHT } from "./looks.js";

const Row = slat({ ...NIGHT, css: [NIGHT.css, own] }, (d) => …);
```

So a look is an ordinary object you can export, import, publish or paste: its CSS, and the layout that goes with it (`thickness`, `inset`, `room`).
Use it as it comes with `slat(NIGHT, (d) => …)`, or put your own CSS after it, where it wins.

For a look to land on a chart it wasn't written for, it has to aim at something both charts have.
Class names are no good for that, because each chart picks its own.
What every chart does have is what rhp writes on each block:

| Selector | What it reaches |
|---|---|
| `.rhp-bar`, `.rhp-dot`, `.rhp-tick`, `.rhp-cell`, `.rhp-area`, `.rhp-line` | every block of that kind |
| `.rhp-label[data-rhp-edge="start"]` | the name beside a slat, in the gutter |
| `.rhp-label[data-rhp-edge="end"]` | a label in the gutter after the slat |
| `.rhp-label[data-rhp-at]` | a label at a value on the scale |
| `.rhp-plot[data-rhp-overlap]` | a Plot whose slats share one space |

Here one look is used by two slats built from different blocks, a plain bar and a bar with a dot at each end, and neither one needed a line of CSS of its own:

<Demo name="styling-look" height={330} />

A look aims at what every chart has.
What is particular to one chart, which of its two bars is the track and which is the progress, stays in that chart's own CSS, where the person who built it can see it.

## The variables rhp reads

A few CSS variables change how rhp draws a block.
Their names follow the chart's scale rather than the screen, saying start and end instead of left and right, so the same rule works whether the chart is horizontal or vertical.

| Variable | What it does |
|---|---|
| `--rhp-radius` | rounds a Bar's corners, one length (2px by default). For different corners, use the next two or plain `border-radius`. |
| `--rhp-start-radius`, `--rhp-end-radius` | round one end of a Bar. The end is where its value is; the start is where it begins. |
| `--rhp-gap` | leaves space at the start of a Bar: a gap between stacked pieces |
| `--rhp-label-gap` | the space between a Label and its value (or the chart, for `edge` labels) |
| `--rhp-label-size` | a Label's font size (12px by default) |
| `--rhp-tick-width` | a Tick's width (2px by default) |
| `--rhp-cell-gap` | the space around a Cell (1px by default) |
| `--rhp-toward-end` | a direction to use in gradients: `linear-gradient(var(--rhp-toward-end), …)` fades from a Bar's start to its end |

## Horizontal and vertical

rhp charts can turn: pass `orientation="vertical"` to the Chart.
The variables above follow the chart as it turns.
For anything else, `:horizontal` and `:vertical` target one direction:

```css
.name:vertical { font-size: 11px; }
.bar:horizontal > img { max-width: 300px; }
```

Put them on the slat or on a block.
For an element inside a block, put them on the block: `.bar:vertical .icon`.

## Colors

Inside a slat's CSS, the theme's colors are variables:

- `var(--rhp-ink)` for text, `var(--rhp-muted)` for quieter text, `var(--rhp-grid)` for lines,
- `var(--rhp-series-1)` to `var(--rhp-series-6)` for data,
- `var(--rhp-color)` for the block's own `color`.

The page sets these colors through the theme, described in [colors and themes](/guides/themes/).

## Without the guard

What keeps your page's CSS out of a chart is a set of rules rhp adds for its own elements: the guard.
It undoes what your page might set on every `div` or `span`, such as margins, padding, borders, fonts and transitions.
That takes time: without it, a chart draws 18 to 28% faster in Chrome and Edge, about 30% faster in Safari, and up to 16% faster in Firefox.

When your page's CSS leaves a chart's elements alone, the chart can go without it:

```jsx
<Chart noCssGuard>…</Chart>
```

Or every chart on the page:

```js
import { noCssGuard } from "@bezda/rhp";
noCssGuard(); // where your app starts, before the first chart, on the server and in the browser
```

The prop and `noCssGuard()` are in rhp 2.1.0 and later.

Use `noCssGuard()` on a page made for its charts, such as a poster or an article.
Use the Chart prop for one large chart on a page of small ones: that chart draws as fast as with `noCssGuard()`.
Once one chart says `noCssGuard`, the charts that keep the guard draw 2 to 6% slower, so when every chart on the page can go without it, call `noCssGuard()` instead.

Without the guard, rhp's own CSS works as before: it places and colors every block and keeps hidden slats hidden.
But your page's CSS now reaches whatever rhp doesn't set itself, and CSS like this changes a chart:

| Your page's CSS | What it does to a chart without the guard |
|---|---|
| margins, padding or borders on every `div` or `span` | moves blocks, labels and grid lines off their places |
| a width or height on every `div`, or a minimum or maximum one | resizes bars and slats |
| fonts and text styles on every `span`: `letter-spacing`, `text-transform`, `line-height` | changes labels and axis numbers, and moves them |
| `::before` and `::after` boxes on every `div`, as a clearfix adds | puts extra boxes in slats and in the chart's grid |
| a background, a shadow, rounded corners or an outline on every `div` | draws them on rhp's elements |
| a `transition` on every element | animates the axis numbers and the names beside slats when they change |
| an `animation` on every element | runs it on every block, label and grid line |
| a rule for a class that a slat uses too | reaches that element: a page's `.note` rule, written for a note under the chart, colors a slat's Label that has the class `note` |

The 92 example charts on this site and the 20 in the slat gallery were drawn without the guard under 12 popular stylesheets.
Tailwind (its browser build and its preflight), normalize.css, modern-normalize, sanitize.css, Pico, Water.css, Simple.css and new.css changed none of them.
Bootstrap 5, Bulma and Milligram changed a few, each only through a class name a slat used too: Bootstrap's `.row` and `.mark`, Bulma's `.box`, `.tag`, `.icon` and `.progress`, and Milligram's `.row`.
So with a framework like these, give your slats class names it doesn't use.

The browser's own styles reach a chart without the guard too, on a slat whose root isn't a `div`.
An `<svg>` root cuts off what it draws outside its box, an `<a>` root is blue and underlined, a `<button>` or `<input>` root has the browser's border, background and font, and a `<p>`, `<ul>`, `<h3>` or `<figure>` root has margins that move it off its place.
A `div`, `li`, `span`, `section`, `label` or `table` root looks the same either way.
Set what you need in the slat's CSS, such as `margin: 0` or `overflow: visible`, or use a `div`.

To check a page, draw its charts with and without `noCssGuard`.
If they look the same at rest, when you point at them and when their data changes, your page's CSS leaves them alone.

A page that links rhp's stylesheet itself (see [server rendering](/guides/server/#many-charts-or-islands)) links `@bezda/rhp/rhp-no-css-guard.css` instead and calls `noCssGuard()`.
A chart inside another chart's slat goes without the guard only when the chart around it does too.

## Things to know

- **Hover whatever should react.**
  `.slat:hover .bar { … }` reacts anywhere along the slat, which is an easy thing to point at and lets one rule light up several pieces at once.
  Hover a block instead when the block is the thing being pointed at: one layer of a stack, one book on a shelf, one cell of a heatmap.
- **Put your own transitions on elements inside blocks.** rhp moves blocks with transitions of its own, and a `transition` set on a block replaces them, so the block would jump to new values. Fade a label's text, not the label.
- **The page can still style the chart's box.** Its width, margin, background and border are yours to set on the Chart, with `class` or `style`.
